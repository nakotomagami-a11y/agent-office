## 🛰 Mission: AI providers: local LLM, OpenAI, Anthropic API + subscription

Let Agent Office run its agents on more AI providers: (1) Anthropic subscription via the claude CLI's own login, which is how it works today and stays the default; (2) Anthropic API key; (3) OpenAI API; (4) a local LLM (Ollama / LM Studio / any OpenAI-compatible local server). The first-run wizard gets a new MANDATORY provider step, and Settings lets the user change it later.

Model it on lumafriend (C:\Users\MeiLi\Documents\Lab\luma, read-only reference): apps/desktop/src/lib/chat/backend.ts (the user's choice is strict: no silent fallback to another backend, and an honest 'unavailable' state with a reason), lib/chat/claude-cli.ts, modules/chat/chat-router.ts (the Anthropic/OpenAI API transports), modules/connections/, lib/windows/onboarding-window.ts. Copy the ideas, not code that doesn't fit.

The central question to answer first: Agent Office agents are `claude -p` child processes (packages/domain/src/services/execution/runs.ts, runs/spawn-env.ts). What does each provider need? For example, the claude CLI pointed at another backend through env (ANTHROPIC_API_KEY, ANTHROPIC_BASE_URL plus a gateway for OpenAI/local), versus a separate runner. And what breaks: tools, sessions/--resume, cost tracking, stream-json parsing, model pickers, accounts (CLAUDE_CONFIG_DIR per account), limits/plan detection.

Phases, in order:
1. SCAN: every seat maps its area of the codebase and posts a result with file:line evidence.
2. DESIGN: the coordinator synthesizes one design (data model, settings, wizard step, runtime per provider, error codes, migration, test plan) and posts it.
3. GATE: the coordinator asks the human with a decision-request to start building. No code is written before the human approves in Agent Office.
4. BUILD: seats implement their owned areas on the hub branch.
5. QA: the qa seat reviews every build diff; a MUST-FIX blocks.
6. DONE only when it is genuinely production-ready: pnpm -r typecheck, pnpm -r lint (0 errors), pnpm -r test and node scripts/check-comment-ratio.mjs are all green, QA has no open MUST-FIX, docs are updated, and every provider has been verified end to end where this machine can (subscription and an API key path at minimum; local if a local server is running). Then the coordinator asks the human to close.

Budget does not limit this mission. Stop when it is done and prod ready, not before.

Rules for every seat:
- Your session does NOT load the repo's CLAUDE.md. Read CLAUDE.md, docs/conventions.md (enforced house rules with ids) and docs/architecture.md before writing any code, and follow them.
- Dependencies point one way: domain <- api-contract <- server/web. The UI calls the server over HTTP, never domain services.
- Agents run with stdin closed: nothing interactive.
- Every seat works on the same hub branch. Commit only the files your seat owns, and run `git pull --rebase` before every push. Never force-push.
- This machine has no git identity configured. Commit with `git -c user.name=... -c user.email=...`, copying both values from `git log -1 --format='%an|%ae'`.
- Never run tests with bare tsx --test (see CLAUDE.md: use pnpm test, which sandboxes HOME).
- Do not start dev servers. If you need one for verification, ask the human with kind human-task.
